# Dylan Huang 的 AI Agent 协作心法

一套面向个人开发者、学生和小型团队的 AI Agent 项目协作工作流。

## 这套方法解决什么问题

- 需求不清就开始写代码
- AI 自行猜测文件、接口和架构
- 忽略已有开源方案，过早自研
- 修改范围越来越大
- 没有独立审查和可验证的验收标准
- 长对话结束后无法继续
- 第一版 MVP 被后续修改破坏

## 适合谁使用

- 正在用 AI 做网站、工具或自动化项目的个人开发者
- 希望建立稳定 AI 协作流程的学生
- 需要减少沟通成本的小型项目团队

## 不适合什么情况

这不是自动完成项目的工具，也不能替代产品判断、代码审查和实际测试。涉及生产数据、敏感信息或高风险决策时，应增加人工审批和专业检查。

## 5 分钟快速开始

1. 阅读 [CUSTOM-INSTRUCTIONS.md](CUSTOM-INSTRUCTIONS.md)，把协作原则放入你的 AI 项目指令中。
2. 复制 [prompts/github-research.md](prompts/github-research.md)，让 AI 先调研可复用方案。
3. 方案确认后再开始实现最小 MVP。
4. 用 [prompts/independent-review.md](prompts/independent-review.md) 在独立上下文中审查方案。
5. MVP 通过验证后，使用 [templates/MVP-ARCHIVE.md](templates/MVP-ARCHIVE.md) 归档。
6. 长对话结束前，使用 [templates/HANDOFF.md](templates/HANDOFF.md) 保存项目状态。

## 推荐流程

1. 配置项目协作指令，明确最小假设、最小改动和验证要求
2. 明确目标用户、任务边界和成功标准
3. 先分析问题，不立即写代码
4. 调研现有开源项目、Skill 和组件
5. 比较直接使用、基于现有方案修改和自己开发
6. 确认方案后再实现最小 MVP
7. 使用独立上下文审查需求和方案
8. 根据任务复杂度选择模型
9. 完成 MVP 后建立可恢复存档
10. 用 HANDOFF.md 延续长周期项目

## 可以直接复制的最小提示词

```text
先不要写代码。请先明确目标用户、输入、输出、必须完成的功能、明确不做的内容和成功标准。
然后调研可以直接使用或二次开发的开源项目、Skill 或组件，检查维护状态、许可证、部署难度和可复用功能。
选出最适合的 3 个方案进行对比，并说明应该直接使用、基于现有方案修改，还是自己开发。
最后给出最简单的 MVP 方案。等我确认以后再开始实现。
```

## 常见问题

### 这是一套万能提示词吗？

不是。这是一套默认协作流程，需要根据项目规模、风险和技术栈调整。

### 为什么要开新的对话审查？

独立上下文可以减少原方案对审查过程的影响，但它不能替代测试、运行验证和人工判断。

### 为什么要保存 MVP？

后续修改可能引入回归。保留可恢复版本，才能安全比较和回滚。

### 一定要使用最贵的模型吗？

不一定。需求拆解、方案比较和风险审查适合能力更强的模型；明确的执行、整理和局部修改可以使用成本更低的模型。
